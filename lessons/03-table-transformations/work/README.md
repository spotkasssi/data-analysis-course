# Отчёт по практике 3

**ФИО и группа:** Кулик Георгий, Т26ОАД-Т.МО31.

## A. Разворот сводки

Сначала решения сгруппированы по организации, году и коду исхода. После `pivot` строки соответствуют ключам организации (`lei`, `activity_year`), а столбцы — исходам. Пустая ячейка означает, что сочетание в данных не встретилось. `pivot` требует уникальности каждой комбинации индекса и столбца, поэтому исходные решения сначала агрегированы.

## B. Обратное преобразование

Отсутствующие сочетания заменены нулями, широкая таблица преобразована обратно через `melt`, а названия исходов сопоставлены исходным кодам. Нулевые сочетания удалены перед сравнением: в исходной длинной сводке представлены только наблюдавшиеся комбинации. `assert_frame_equal` проверяет совпадение сводок после сортировки.

## C. Проверка соединения

Название организации добавлено через LEFT JOIN по `lei` и `activity_year` с `validate="many_to_one"`. После соединения исходные столбцы сравниваются с исходными данными в порядке `source_row`. Дополнительная проверка намеренно меняет значение `loan_amount` и убеждается, что сравнение замечает изменение. Проверки только числа строк недостаточно: значения могут измениться при той же длине таблицы.

## D. Покрытие справочника

В ноутбуке создаётся частичный справочник и сравниваются LEFT JOIN и INNER JOIN. LEFT JOIN сохраняет все решения и отмечает строки без соответствия; INNER JOIN исключает такие строки. Результаты проверки покрытия сохраняются в `unmatched.csv` и `join_audit.json`. Повтор ключа в справочнике размножает совпавшие строки; `validate="many_to_one"` должен остановить такое соединение.

## E. Профиль организаций

Профиль рассчитывается по организации и году из исходных решений. `n_decisions` — число решений, `n_approved` — число решений с кодами 1 и 2, `approval_rate` — отношение этих величин. Имя добавляется LEFT JOIN с проверкой уникальности ключа профиля. Итог сохраняется в `organization_profile.csv`.

## Передача

Ноутбук использует `decisions.csv` и `organizations.csv` из папки данных занятия. Единица анализа — организация в конкретном году; ключ справочника — `lei` и `activity_year`. Общая доля одобрения считается как сумма одобренных решений, делённая на сумму всех решений. Она отличается от простого среднего долей организаций: в среднем каждая организация получает одинаковый вес независимо от числа решений. Выводы описывают только предоставленные данные и не устанавливают причины одобрения или отказа.

Для воспроизводимой сдачи выполните **Restart Kernel → Run All** и убедитесь, что в папке `results` появились три CSV/JSON-файла, перечисленные выше.
