# Отчёт по практике 3

ФИО и группа: заполнить самостоятельно.

## A Разворот сводки

Сводка `long` содержит по одной строке на ключ организации (`lei`, `activity_year`) и исход (`action_taken`). После `pivot` строки соответствуют ключам организации, а столбцы — исходам. Пустая ячейка означает, что сочетание не встретилось в исходных данных, а не неизвестное число решений. Для `pivot` комбинации индекса и столбца должны быть уникальны; поэтому сначала агрегировали исходные решения.

## B Обратное преобразование

Пустые сочетания заменены нулями, столбцы исходов переименованы и таблица развёрнута обратно через `melt`. После преобразования исходы сопоставлены кодам 1–3, нулевые сочетания удалены, строки отсортированы. `assert_frame_equal` подтверждает совпадение с исходной длинной сводкой. Нули исключены, потому что исходная сводка содержит только наблюдавшиеся сочетания.

## C Сохранность исходных значений

Имя добавлено левым соединением по `lei` и `activity_year` с `validate="many_to_one"`. Сверка исходных столбцов после сортировки по `source_row` подтверждает сохранность значений. Отдельная проверка намеренно меняет `loan_amount` и подтверждает, что сравнение обнаруживает изменение. Проверки только длины недостаточно: при том же числе строк значения могут быть подменены или строки переставлены.

## D Покрытие неполного справочника

При удалении одной записи из справочника LEFT JOIN сохраняет все 6 830 решений, а INNER JOIN оставляет 6 805; 25 решений не находят соответствия. Они записываются в `unmatched.csv`, а сводка проверок — в `join_audit.json`. Дублирование ключа справочника увеличивает результат соединения до 6 855 строк: совпавшие решения размножаются. `validate="many_to_one"` останавливает такое соединение.

## E Передача профиля

Профиль строится из исходных решений по организации и году. `n_decisions` — число решений; `n_approved` — число решений с кодами 1 и 2; `approval_rate` — их отношение к числу всех решений организации. В профиле 314 групп, всего 6 830 решений и 6 139 одобренных/выданных решений; общий показатель равен примерно 89,85%. Справочник присоединён LEFT JOIN с проверкой `one_to_one`. Результат сохраняется в `organization_profile.csv`.

## Итог

Источник — файлы `decisions.csv` и `organizations.csv` из каталога данных занятия. Строка исходной таблицы — отдельное решение; ключ организации — `lei` и `activity_year`. Соединение со справочником выполняется по этим полям, с проверкой уникальности правой стороны и сохранности строк. Общий показатель одобрения рассчитан как сумма одобренных решений / сумма всех решений; он не равен простому среднему ставок организаций, поскольку последнее одинаково взвешивает организации независимо от числа решений. Данные описывают только имеющиеся решения и не доказывают причин одобрения или отказа.
